## 로컬 검증

빌드 경고/오류 0, 순수 C# 회귀 44개 통과. 설치된 DLL의 앵커 검사는 이름 메타데이터 확인으로 런타임 동작을 보장하지 않는다. 한글 카탈로그 검수와 새 기능 검수는 별도 범위다.

## 현재 입력·수집 조사

공용 IsPlayerBlocked/IsPlayerActionBlocked 결과를 패널 상태로 바꾸던 훅을 제거했다. 게임의 키 해제·차단 상태 갱신은 그대로 두고 F8 동안 이동 입력은 메서드 호출 범위에서만 0으로 임시 주입한다. 회전/상호작용/공격은 조작 시작점만 제한한다. 입력 차단 플래그나 ForceUnblock은 쓰지 않는다. 상태 변경은 input 로그에 기록한다.

수집은 반경 확장만으로 native Update 호출을 가정했던 방식에서 PerformProximityScan 호출로 보완했다. native/mod 스캔은 공유 cadence로 중복을 막고 죽음/인벤토리/유예/게임 상태를 존중한다. 가시선은 아이템 소유 Transform 기준으로 같은 물체의 자식 콜라이더를 허용한다. 후보/검사 통계는 실제 수집 완료를 의미하지 않는다.

## 층 전환·자동줍기 후속 수정

씬 unload만으로는 같은 씬의 던전 재생성/재사용 지도 텍스처를 무효화하지 못한다. BeginGeneration/ClearDungeon 및 InitializeMap 훅은 OnUpdate로 갱신 요청만 전달한다. DungeonManager.currentFloor 변화도 감지한다. 새 층에서 입력 임시 값·수집 반경·목적지·요정·지도 레이어·오류 차단 상태를 정리하고 싱글턴은 다시 읽는다. 싱글턴 필드가 비어 있으면 이미 로드된 활성 컴포넌트만 제한 주기로 검색하며 생성 getter를 호출하지 않는다. 지도 버퍼 재작성은 revision을 올려 같은 텍스처에서도 모드 복사본을 새로 만든다.

설치 게임의 native PerformProximityScan과 TryPickup은 OptionsManager.IsAutoPickupEnabled가 false이면 후보 검사 전 반환한다. 이전 후보 0개 로그와 맞는 실패 조건이며 사용자 설정값 자체는 아직 런타임 확인 전이다. 모드 활성·안전 상태에서 허용된 native scan 호출 동안만 getter 결과를 허용하고 finalizer로 호출 범위를 정리한다. 설정 저장, 아이템 CanAutoPickup, 무게 제한, 인벤토리/죽음 유예는 변경하지 않는다. native Update와 모드 호출 모두 동일 scope/cadence를 사용해 먼저 실행된 native scan이 비활성 옵션 때문에 공유 주기를 소모하는 문제도 피한다. 세 가지 순수 scope 회귀 테스트가 호출 외 설정 유지, 예외 정리, 중첩 호출을 검증한다.

소유자가 후속 설치본에서 층 갱신·자동줍기 모두 정상이라고 확인했다. 소유자는 현재 플레이 중 입력도 정상이라고 보고했다. 간헐적 재발은 장시간 관찰 범위이며 자동 이동은 별도 검증 범위다. 스캔 후보·가시선 검사 로그도 더 이상 0으로 고정되지 않지만 이 통계는 수집 성공 개수가 아니다.
